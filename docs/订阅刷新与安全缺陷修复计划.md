# 订阅刷新与安全缺陷修复计划

## 目标与边界

本次修复覆盖真实迁移数据、部署文件、后端、前端和 Go 测速服务中已经复现或能由代码路径直接证明的缺陷，重点是：

- 首次 Docker 部署时挂载目录不存在或不可写，导致应用无法创建数据文件并启动。
- 订阅凭据、代理凭据、登录会话及错误日志的泄露风险。
- 手动更新被锁、锁句柄残留、重复刷新、旧结果覆盖新结果及批量刷新误报成功。
- 多个订阅同时在 0 点执行时部分任务遗漏、失败状态不准确或已删除任务残留。
- 无效或零节点订阅覆盖正常 YAML，造成节点丢失或长期返回旧配置。
- 节点、代理链、用户分配、分组配置和端口映射使用易变化名称或数组下标，导致改名、刷新、重排或删除后引用错位。
- 配置导入、GeoIP、自定义代理、测速服务和文件写入边界中的高风险安全缺陷。

迁移后的 `data` 目录只用于只读验证，不执行迁移脚本改写业务配置。`ddns_sync.py` 和用户已有的 `.gitignore` 修改不属于本次修复。Compose 中用户明确要求的应用镜像 `ghcr.io/socialyjj/clash-sub-merger:latest` 保留；其余构建基础镜像不使用 `latest`。

## 阶段一：真实数据与日志核验

**状态：已完成。**

### 已完成内容

- 为迁移后的 `data` 目录建立修复前 SHA-256 基线，共 21 个文件、6,339,441 字节。
- 当前数据包含 8 个启用的 URL 订阅，均配置为 `0 0 * * *`。
- 历史日志中确认了定时刷新失败、已删除订阅的残留任务、零节点结果被视为成功、备份写入失败和任务恢复失败。
- 确认旧用户配置中存在完整 YAML 缓存，具备长期返回旧配置和持续放大 `config.json` 的条件。
- 确认 `refresh_locks` 中存在历史锁文件；锁文件存在本身不表示操作系统锁仍被持有，因此不能通过删除所谓“陈旧锁文件”解锁。
- 当前配置直接经过新校验器会因历史残留来源失败；仅在内存中清理可信旧配置残留后可通过，共识别 4 个清理单元，未写回迁移数据。

### 关键决策

- 不输出、复制或写入订阅 URL、Token、节点凭据和代理凭据。
- 首次部署问题在容器挂载目录边界解决，不依赖用户预先手工创建 `data`、子目录或配置文件。
- 刷新失败必须保留可诊断但已脱敏的错误类别；不能再把失败、空响应或零节点标记为成功。

## 阶段二：首次部署、认证与敏感信息

**状态：已完成。**

### 已完成内容

- 新增容器入口脚本，创建 `uploads`、`logs`、`backups`、`refresh_locks`，处理绑定目录所有权，验证真实写权限后再通过 `gosu` 降权启动应用。
- 应用进程保持非 root；root 仅用于入口阶段修复挂载目录权限。
- 目录初始化失败不再被静默吞掉；不可写目录会明确终止启动。
- Docker 构建上下文排除 `.env`、`data`、运维脚本、测试和本地产物，避免把服务器数据或凭据打入公开镜像。
- 公开认证状态接口不再返回订阅 Token 或文件名；删除会重新引入旧全局 Token 的接口。
- 登录会话改为哈希存储，支持会话签名密钥、过期区分和旧明文会话的一次性迁移。
- 首次设置和密码修改统一使用 PBKDF2 密码哈希及密码策略；配置导入限制 PBKDF2 工作因子，避免恶意配置造成登录 CPU 拒绝服务。
- Uvicorn 查询参数访问日志默认关闭；订阅抓取、HTTP 错误、GeoIP 和解析错误不再记录 URL、Token 或代理凭据。
- 代理设置读取不返回已保存凭据；凭据只能替换或显式清除，连接失败也不回显代理 URL。
- 配置导出和备份明确包含密码哈希及订阅 Token，但移除登录会话，并通过不可缓存响应头降低浏览器缓存风险。

### 后续部署要求

- 历史日志中曾出现过的订阅凭据应视为已泄露，必须在供应商侧轮换，并清理服务器及反向代理的旧日志副本。
- 反向代理仍需关闭或脱敏包含订阅 Token 的查询参数访问日志；应用无法清理代理服务器已经记录的日志。

## 阶段三：订阅刷新与调度一致性

**状态：已完成。**

### 已完成内容

- 前端仅对幂等 GET 请求自动重试；刷新、更新、删除等写操作不再因超时被自动重放。
- 手动、批量、定时和缺文件刷新统一使用跨进程文件锁；同一订阅只允许一个写入者，不同订阅仍可受控并发。
- 异步刷新使用 `AsyncFileLock`，避免 `asyncio.to_thread()` 在不同工作线程获取和释放普通 `FileLock` 时遗留 Windows 文件句柄。
- 锁冲突返回 HTTP 409 和 `Retry-After`；不再按文件时间删除锁文件。
- 单订阅刷新超时调整为 180 秒；批量刷新返回准确的成功、失败、总数及逐项结果，不再把部分失败整体报为成功。
- 仅对连接、DNS、超时、HTTP 408、429 和 5xx 进行有限重试；确定性客户端错误不重复请求。
- 订阅直连、代理抓取、本地 Go 服务及相关测试请求显式禁用环境代理，避免服务器的 `HTTP_PROXY` 意外接管流量。
- 调度器配置独立工作线程池、错过任务宽限和随机错峰；多个 `0 0 * * *` 任务不再集中争抢同一秒。
- 禁用或删除订阅时同步删除任务；重新启用或修改 Cron 注册失败时回滚配置。
- 定时执行前重新核验订阅存在、启用且不是本地订阅；残留任务会被移除并记录失败状态。
- 空响应、HTML、无法解析内容和零节点内容均视为失败，不覆盖旧 YAML。
- YAML 与配置记录采用“临时文件—原子替换—失败回滚”的完整操作，避免只更新其中一侧。
- 停止读写完整 YAML `sub_cache`，所有节点、分配、模板和代理链变化会使相关派生缓存失效。

## 阶段四：稳定引用、配置边界与安全加固

**状态：已完成。**

### 节点与代理链一致性

- 自定义节点、订阅节点、代理链行和代理池均使用稳定 ID；不再依赖数组下标或易变化的显示名称。
- 节点技术配置变化时，仅在同名匹配唯一且无歧义时迁移引用；重名节点不会被错误重定向。
- 删除订阅会清理用户分配、代理链、分组配置、端口映射、测速结果和代理设置中的所有归属引用。
- 代理链改名、行删除、行重排、代理池改名会按稳定组件身份迁移或删除引用，不再把第二行误当成第一行。
- `group_config` 和 `port_mappings` 中的代理链对象持久化为稳定 ID，在生成具体订阅时再解析为当前名称。
- 模板分组名与代理链池名碰撞时，生成名称使用稳定组件后缀；分组配置和监听端口仍指向正确代理池。
- 修复管理员订阅生成代理池时条件导入遮蔽顶层 `ProxyGroupGenerator` 导致的 HTTP 500。
- 内置分组编辑器与实际订阅输出统一使用同一套默认模板和分组名称；管理员 Token 的分组配置会真实影响输出。

### 外部输入与配置

- 用户分配、用户和管理员分组配置、来源排序、代理链结构及端口范围在 API 边界校验一次。
- 外部配置导入严格拒绝未知来源、重复 ID、重复 Token、路径型 ID、无效密码哈希和失效代理链来源。
- 可信旧备份或当前配置迁移允许清理已删除订阅残留、旧 `custom` 来源及失效 `source_order`；外部新导入不会静默清理后接受。
- 配置导入或备份恢复后的运行时重载失败会原子恢复旧配置。
- `config.json.backup` 和 GeoIP 缓存采用临时文件后原子发布；发布失败会清理未发布临时文件。

### GeoIP、测速与网络边界

- 自定义 GeoIP URL 拒绝凭据、环回、链路本地、私有地址及解析到任一私网地址的主机。
- GeoIP 请求禁用环境代理和重定向，并限制响应体大小；查询和 API 测试接口增加限流。
- 自定义 GeoIP Token 省略、替换、清除语义明确；读取配置不返回 Token。
- Python 和 Go 测速请求复用客户端、限制并发和超时，拒绝空批次及异常参数。
- Go 拨号代理错误不再回显凭据；代理拨号路径增加回归测试。
