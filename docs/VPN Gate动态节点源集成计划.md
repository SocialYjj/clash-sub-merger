# VPN Gate 动态节点源集成计划

## 目标

将 VPN Gate 的 OpenVPN 节点列表接入现有项目，使用户可以在创建链式代理时选择单个 VPN Gate 节点，或将多个 VPN Gate 节点作为最后一跳落地池；通过系统设置配置全局自动刷新间隔，并将节点缓存保存在当前数据库后端。

## 阶段 1：后端节点源与缓存（已完成）

- [x] 新增 VPN Gate API 下载、CSV 解析和 OpenVPN 配置解析服务。
- [x] 将解析后的节点缓存写入数据库缓存文档，不写入 `data` 目录。
- [x] 为节点生成稳定 ID，保存最后发现时间、最后刷新时间和失效状态。
- [x] 刷新只在完整下载和解析成功后替换当前快照；失败时保留上一份可用缓存。
- [x] 增加手动刷新、查看状态和节点列表接口。

## 阶段 2：链式代理与导出（已完成）

- [x] 允许 `openvpn` 节点通过过滤器和配置校验。
- [x] 将 VPN Gate 作为一个动态池加入链式代理编辑器；单个 VPN Gate 节点不再占用选择器列表。
- [x] 在节点引用解析、配置导入校验和节点池引用中支持 `vpngate` 来源。
- [x] 复用现有链式代理的 `dialer-proxy` 生成逻辑，由链路第一跳动态决定前置节点。
- [x] 仅在 Clash/Mihomo 输出中生成 OpenVPN 节点；不支持的导出格式返回明确诊断，不静默生成错误配置。

## 阶段 3：自动刷新与系统设置（已完成）

- [x] 在系统设置中增加 VPN Gate 更新开关、刷新间隔、立即刷新按钮和最近一次刷新状态。
- [x] 使用现有 APScheduler 注册一个全局 VPN Gate 刷新任务，避免每条链重复调度。
- [x] 链式代理保存稳定引用；落地池随最新有效节点快照更新，单节点失效时不自动替换。
- [x] 订阅输出使用最新成功缓存；已导入客户端在下次更新订阅后获得新配置。

- [x] 集成测试覆盖“前置节点 → VPN Gate 单节点”和“前置节点 → VPN Gate 落地池”。
- [x] 运行后端测试、前端构建和 Mihomo 配置检查，确认不会影响现有订阅、链式代理和节点池行为。

## 关键决策

- VPN Gate 脚本中的固定 `FRONT-VLESS` 只作为独立脚本行为保留，不直接复制到项目；项目中的前置节点由链式代理第一跳决定。
- 不使用脚本中的 `127.0.0.1:10808` 作为 VPS 固定代理；后端使用直连或项目已有的服务器代理配置。
- VPN Gate 证书、私钥和完整 OpenVPN 配置只保存在后端数据库缓存，不通过前端节点列表接口展示。
- 第一版只承诺 Clash/Mihomo 导出能力。
- VPN Gate 动态池保存 `group_source: vpngate`，只保留池引用和策略；生成订阅时按当前有效缓存展开节点。
